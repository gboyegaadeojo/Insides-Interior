## PDF spike (SPEC 10.4)

**Setup.** `/spike/pdf-sample` renders a static 3-page quote (Letter, five rooms, about 58 lines, Fraunces
headings, Inter body, SVG logo, CSS page breaks). `/spike/pdf?key=<SPIKE_KEY>` launches Browser Rendering
through `@cloudflare/puppeteer`, waits for `load` and `document.fonts.ready`, prints with `page.pdf()`, stores
the file in R2 at `pdf/spike/1/<sha256>.pdf` and returns the PDF (timings in `Server-Timing`).
`&format=json` returns the timings, page count, byte size and the fonts that loaded.

**Result.** _Filled in after the first production run; see below._

**Local development.** Under `wrangler`/`vite dev` on Windows the local Browser Rendering shim launches a
downloaded Chrome (about 0.4 s) and loads the page, but `page.pdf()` never returns, even with a 120 s
timeout. The spike must therefore run against the deployed Worker. Real PDFs aren't needed locally until
phase 5; if they still hang then, phase 5 adds a dev-only fallback.
